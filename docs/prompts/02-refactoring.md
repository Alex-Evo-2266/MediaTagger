# Промпт-шаблон: рефакторинг существующего кода

## 1. Назначение

Шаблон предназначен для улучшения структуры и читаемости существующего кода без изменения его функциональности.

## 2. Промпт по структуре RTCF

### Role — роль

Ты опытный разработчик TypeScript и React, специализирующийся на рефакторинге существующих приложений. Твоя задача — улучшать качество кода, сохраняя его корректную работу.

### Task — задача

Выполни рефакторинг `[название файла, функции или компонента]`.

Цель рефакторинга: `[описание проблемы, которую необходимо решить]`.

Перед внесением изменений изучи текущую реализацию и определи, какие изменения действительно необходимы.

### Context — контекст

- Проект MediaTagger — настольное приложение для каталогизации изображений.
- Основные технологии: React, TypeScript, Electron и MUI.
- Соблюдай инструкции из `.github/copilot-instructions.md`.
- Учитывай разделение приложения на main, preload и renderer.
- Используй существующие типы и соглашения проекта.
- Сохраняй публичные интерфейсы, формат хранения данных и текущее поведение.
- Не добавляй новые библиотеки без необходимости.
- Не переписывай несвязанные участки кода.
- Не удаляй существующую функциональность ради упрощения реализации.

### Format — формат результата

Предоставь результат в следующем формате:

1. Опиши обнаруженные проблемы в коде.
2. Объясни, какие изменения предлагаешь и зачем.
3. Выполни минимально необходимый рефакторинг.
4. Перечисли изменённые файлы.
5. Укажи проверки, которые необходимо выполнить.
6. Сообщи, были ли проверки запущены и каковы их результаты.

Если рефакторинг не даёт существенных преимуществ или может нарушить работу приложения, объясни это до внесения изменений.

## 3. Пример использования

Проведи рефакторинг функции обработки тегов в `GalleryStore`.

Проверь, есть ли повторяющийся код, избыточные проверки или сложные для понимания участки. Если можно улучшить структуру без изменения поведения, внеси минимальные изменения.

Не меняй формат JSON-хранилища, существующие типы данных и интерфейсы методов, которые используются другими частями приложения.

## 4. Критерий готовности

Шаблон считается готовым, если его можно использовать для улучшения разных участков кода MediaTagger, сохраняя существующее поведение приложения и ограничивая изменения рамками поставленной задачи.
